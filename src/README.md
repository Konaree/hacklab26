# Nexys A7: плейлист WAV с microSD

Расширение загруженного проекта: до 16 треков, автоматический переход и кнопки
выбора. Всё работает в одном домене 100 МГц. IP Catalog, Block Design, MicroBlaze,
AXI, XBAR и генераторы памяти не используются.

## Управление

| Действие | Результат |
|---|---|
| Включение / CPU_RESETN | Инициализация SD, поиск файлов, запуск первого трека |
| BTNR | Следующий трек с начала; после последнего — первый |
| BTNL | Предыдущий трек с начала; перед первым — последний |
| Конец трека | Автоматический запуск следующего |
| Конец последнего трека | Остановка, status 0x06; повторный запуск кнопкой |
| Единственный трек и любая кнопка | Повторный запуск этого трека |
| Обе кнопки одновременно | Команда игнорируется |

Короткое нажатие должно длиться хотя бы около 10 мс. После двухтриггерного
синхронизатора используется фильтрация дребезга 10 мс. Удержание кнопки не
создаёт повторных переключений. Отпускание также должно пройти фильтрацию.
Кнопки, нажатые до завершения поиска файлов, не выбирают трек; первый трек
запускается автоматически.

Выбранный трек всегда начинается сначала. Переход BTNL не означает перемотку
текущего трека назад. Громкость, пауза и перемотка в этой версии не добавлялись.

## Файлы на карте

1. Используйте прежнюю карту SDHC/SDXC с MBR и первым разделом FAT32.
2. Запишите WAV-файлы в корневой каталог. Специальное имя `TRACK001.WAV`
   больше не требуется. Для предсказуемых коротких имён удобно использовать
   `TRACK001.WAV`, `TRACK002.WAV`, `TRACK003.WAV` и т. д.
3. Все треки должны иметь прежний формат: PCM, 8 бит без знака, моно,
   48000 Гц, канонический WAV-заголовок 44 байта.
4. Каждый файл должен занимать последовательные кластеры. Разные файлы
   могут располагаться в разных местах: их начальные кластеры определяются
   независимо. Между треками можно оставлять свободные кластеры.
5. Порядок воспроизведения соответствует порядку коротких записей в каталоге,
   **а не алфавитной сортировке имён**. Он часто совпадает с порядком копирования,
   но полагаться на это без проверки каталога нельзя.

Пример нормализации уже перекодированных входных WAV:

```text
python prepare_wav.py first.wav TRACK001.WAV
python prepare_wav.py second.wav TRACK002.WAV
python prepare_wav.py third.wav TRACK003.WAV
```

Скрипт, как и раньше, не декодирует MP3 и не меняет частоту дискретизации:
на входе уже нужен PCM U8, моно, 48 кГц.

## Границы поддержки FAT32

Это расширение прежнего ограниченного проигрывателя, а не полный драйвер FAT32.
Поиск проходит по **всем секторам первого кластера корневого каталога**, а не
только по первому сектору, как раньше. Максимальный размер кластера — 128
секторов, как в исходном разборе BPB.

Поиск останавливается при первом маркере конца каталога, при нахождении 16
треков или в конце первого корневого кластера. Продолжение каталога по цепочке
FAT не обходится; фрагментированные файлы по-прежнему не поддерживаются.
Проверка FAT-цепочек на непрерывность также не выполняется.

В плейлист входят обычные короткие записи с расширением `WAV`, кластером >= 2
и размером >= 44 байт. Исключаются удалённые записи, каталоги, метки тома и LFN.
Для файла с длинным именем используется соответствующая короткая запись,
если её расширение равно `WAV`; само длинное имя не сохраняется и не выводится.
Скрытые и системные обычные WAV-файлы не исключаются.

Заголовок каждого файла проверяется при его запуске. Если WAV неподдерживаемый,
проигрыватель останавливается с 0xE5; BTNR/BTNL позволяют выбрать другой файл.
Ошибки транспортного контроллера SD (LED[7]) требуют общего сброса.
Переход между файлами содержит короткий интервал тишины; бесшовное склеивание
треков и подавление щелчков не реализованы.

## Что заменить в Vivado

В архив включён полный комплект:

- `rtl/fat32_wav_player.sv` — поиск плейлиста и переключение треков;
- `rtl/nexys_sd_wav_top.sv` — подключение кнопок и их фильтрация;
- `rtl/sd_spi_sector.sv` и `rtl/spi_byte_master.sv` — без изменений относительно
  файлов, загруженных с запросом;
- `nexys_sd_wav.xdc` — прежние выводы плюс BTNL и BTNR;
- `prepare_wav.py` — прежний скрипт без изменений.

Замените исходники и XDC, удалите прежние дубли определений модулей из проекта,
оставьте `nexys_sd_wav_top` верхним модулем. Новый модуль
`track_button_debouncer` находится в том же файле, что верхний модуль; отдельный
IP или дополнительный `.sv` для него не нужен.

**Обязательно замените XDC:** BTNL подключён к P17, BTNR — к M17.
Выводы сверены с [официальным Master XDC Digilent](https://github.com/Digilent/digilent-xdc/blob/master/Nexys-A7-100T-Master.xdc).

Выполните Reset Runs для `synth_1` и `impl_1`, затем повторите синтез,
имплементацию и создание битстрима. Исходники тестов из `tests` не добавляйте
в Design Sources; для симуляции используйте Simulation Sources.

Для отдельного запуска проверок Vivado:

```text
vivado -mode batch -source scripts/check_vivado.tcl
```

Скрипт создаёт отчёты и контрольные точки в `build/vivado`, но не программирует
плату и не создаёт битстрим автоматически.

## Внутренние изменения

Плейлист хранит только начальный кластер и размер каждого файла: 16 × 64 бит.
Заголовки и звуковые данные всех треков одновременно не загружаются.

При переключении отключается звук, текущий сектор дочитывается контроллером
SD, его оставшиеся данные игнорируются. Затем сбрасываются указатели,
заполненность FIFO, признак предвыборки, позиция файла, длина данных и ошибка
заголовка. Новый WAV читается с нулевого смещения. Инициализация карты и
повторный поиск каталога при обычном переключении не выполняются.

Новые входы `fat32_wav_player`: `next_track`, `prev_track` — одиночные тактовые
импульсы. Новые выходы: `track_index[3:0]` (0…15), `track_count[4:0]` (0…16).
На плате они доступны для внутренней отладки; вывод LED остался диагностическим.
Статусы 0x01…0x06 и ошибки 0xE0…0xE5 сохранены.

Управление проигрывателем, включая адресные регистры аудиопамяти, теперь
использует синхронный сброс. Содержимое RAM не сбрасывается. Нижние модули SPI
сохранены без изменений; весь DRC необходимо проверить в Vivado, предупреждения
не подавляются. В верхнем модуле добавлено синхронное снятие внешнего сброса.

Выдача сэмплов сохранена из присланной версии: чтение FIFO при импульсе
`sample_tick`, вывод предвыбранного сэмпла при следующем импульсе.

## Проверки

`VALIDATION.md` описывает 20 пройденных сценариев, включая полную симуляцию
верхнего модуля с обменом по выводам SPI и нажатием BTNR.

Для повторного запуска нужны Python 3, Verilator и компилятор C++:

```text
python tests/run_tests.py
```

Скрипт сам создаёт искусственные образы для тестов. Это не образы настоящей
карты; на физическую SD-карту их записывать не нужно.

Vivado и физическая плата в этой среде недоступны. Работа реального битстрима,
временные ограничения внешнего SPI и качество аналогового звука здесь
не проверялись.
